CURRENT REAL-WORLD FIX

A real Telegram photo was visibly a shopping receipt but was photographed sideways, occupied only part of the frame, and included fingers/background. The prior classifier returned is_receipt=false.

The code now treats these as normal user conditions:
- 90/180/270 degree rotation;
- tilted/perspective photos;
- receipt occupying only part of the image;
- fingers, desk/carpet/background clutter;
- folds, shadows and imperfect framing.

If the first Vision pass returns is_receipt=false, the Worker automatically performs one second verification pass on the same downloaded image. The user must NOT be asked to resend between those two passes.

The second pass explicitly checks all four orientations and looks for receipt evidence such as narrow thermal paper, item/quantity/price rows, totals, payment details, merchant/time or barcode. Only if both passes reject the image should it be treated as a non-receipt.

The same safety rules remain: successful recognition still must pass confidence and amount reconciliation before any transaction is written.
