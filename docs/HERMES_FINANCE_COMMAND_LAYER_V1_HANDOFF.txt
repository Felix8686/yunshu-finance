Purpose:
Replace the growing set of sentence-specific finance intents with a generic model-driven command layer.

Implemented command actions:
- create
- query
- summarize
- update
- delete
- restore
- passthrough

Key design:
- LLM maps natural language to a fixed FinanceCommand schema.
- Program code resolves actual ledger targets and executes validated operations.
- LLM never invents transaction IDs and never directly accesses D1.
- create supports transactions[] so Telegram creation does not require a second LLM parse.
- update/delete refuse ambiguous matched targets when count is not explicit.
- delete is reversible: the active transaction is removed, but a complete transaction + transaction_items snapshot is persisted in ledger_operations.
- restore recreates the deleted transaction and its transaction_items from the audit snapshot.
- update/delete/restore operations are recorded in ledger_operations.
- D1 batch is used for multi-step mutations.
